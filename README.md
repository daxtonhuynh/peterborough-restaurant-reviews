# Peterborough Restaurant Review Analytics

An end-to-end NLP pipeline that reads **7,073 public Google reviews of 25 Peterborough restaurants** (January 2024 – June 2026) sentence by sentence, measures sentiment on 15 aspects of a visit, links complaints to 1–2 star ratings, benchmarks each restaurant against its operational peer group, and turns the gaps into action plans.

**Case study:** https://daxtonhuynh.github.io/peterborough-restaurant-reviews/

## Headline findings

- Diners are overwhelmingly satisfied: 89.2% of reviews are 4–5 stars, so ratings are decided by a small number of failures.
- A complaint about cooking execution (freshness, temperature, doneness) carries the strongest link to a 1–2 star rating: **+12.3 percentage points**, ahead of staff (+9.9), cleanliness (+8.0), food (+6.5) and waiting (+6.5).
- Problems compound: 1.7% of reviews with no complaint are 1–2 stars, against 27% with one, 57% with two and 74% with three or more.
- Speed & waiting is the weakest frequently mentioned aspect (net sentiment +0.30), and its complaint rate rose from 4.4% to 5.6% of text reviews in the last 12 months.

## Pipeline

Each step reads only the outputs of earlier steps and writes to its own numbered folder in the workspace. Re-running 07 → 08 → 09a → 09b after any label change regenerates every figure.

| Step | Script | What it does | Main outputs |
| --- | --- | --- | --- |
| 01 | `01_build_analysis_ready_dataset.py` | Audit, clean and enrich the merged review export (25 restaurants); nothing is deleted, anomalies are flagged | `02. Outputs_Data Mining/reviews_analysis_ready.parquet` |
| 02 | `02_market_eda.py` | Market EDA: ratings, trends, peer groups; writes the EDA notebook | `03. Outputs_EDA/eda_summary.xlsx`, charts |
| 03 | `03_generate_report.py` | EDA report as Word | `03. Outputs_EDA/EDA_Report.docx` |
| 04 | `04_prepare_nlp_segments.py` | Language resolution; spaCy sentence and clause segmentation with character offsets | `04. Outputs_NLP/review_sentences.parquet`, `review_clauses.parquet` |
| 05 | `05_bertopic_discovery.py` | BERTopic in five runs (all, negative, positive, by peer group, last 12 months) | `05. Outputs_BERTopic/run*/topics.parquet` |
| 04b | `04b_build_absa_units.py` | Split run-on sentences into ABSA units; inherits topics from step 05, so it runs after 05 | `04. Outputs_NLP/absa_units.parquet` |
| 05b | `05b_taxonomy_v1_1_and_pilot_v3.py` | Topic → aspect mapping v1.1 and the stratified 200-sentence pilot | mapping v1.1, pilot workbooks |
| 05c | `05c_llm_prelabels_pilot_v3.py` | Load LLM pre-labels into the pilot for human verification | `annotation_pilot_v3_prelabelled.xlsx` |
| 05d | `05d_codebook_v1_2.py` | Codebook v1.2: boundary decisions and decision log | mapping v1.2 |
| 06a | `06a_pilot_agreement_and_gold.py` | Cohen's kappa (A vs B, LLM vs each human) and the gold file, once the pilot is verified | `06. Outputs_Annotation/` |
| 07 | `07_absa_model.py` | Aspect detection (cue lexicon + TF-IDF logistic regression) and sentiment (VADER + domain rules); DEV/TEST evaluation | `07. Outputs_ABSA/absa_model_evaluation.xlsx`, `models/` |
| 08 | `08_absa_inference.py` | Score all 17,191 units; review-level features; food-safety review queue; convergent validity | `07. Outputs_ABSA/absa_review_features.parquet` |
| 09a | `09a_rating_drivers.py` | Ordered logit, 1–2 star logit with restaurant fixed effects (AMEs), gradient boosting check | `08. Outputs_Analysis/rating_driver_ame.csv` |
| 09b | `09b_market_scorecards_priorities.py` | Peer benchmarks, scorecards, priority score and action plans | `08. Outputs_Analysis/*.xlsx`, `dashboard_data.json` |

`absa_lexicon.py` holds the aspect cue lexicon and sentiment rules used by 07, 08, 09a and 09b.

### Running it

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m spacy download en_core_web_md

# Point the pipeline at a workspace folder that holds the input files (see data/README.md).
# If PTBO_BASE is not set, the repository root is used as the workspace.
export PTBO_BASE="/path/to/workspace"

python pipeline/01_build_analysis_ready_dataset.py
python pipeline/02_market_eda.py
# ... continue in the order of the table above
```

Steps 05b to 06a include manual work: the topic mapping v1.0 is filled in by hand, the LLM pre-labels (`llm_prelabels_v1_claude.txt`) are produced outside the pipeline, and the pilot is verified by the annotators before 06a runs. Random seeds are fixed at 42 (05b sampling, 09a gradient boosting); the DEV/TEST split is fixed by odd/even sample number.

## Data

The reviews are **not** included. They contain reviewers' names and text, and the restaurant-level outputs name individual businesses. `data/README.md` describes the input files and their columns. The aggregate figures shown on the case-study page are in `docs/data/`.

## How far to trust the results

- **Silver labels.** The model is evaluated against 200 LLM pre-labels approved in bulk by the project lead, not verified row by row and without a second annotator, so inter-annotator agreement has not been measured yet. On the held-out TEST half: aspect detection micro F1 0.766, sentiment accuracy 0.795. Step 06a is ready for the upgrade.
- **Associations, not causes.** Rating-driver results describe what goes with low ratings, comparing reviews of the same restaurant.
- **Partial, self-selected sample.** About 41% of each restaurant's listed Google reviews were collected.
- **Food safety.** Possible food-safety reports go to a manual review queue and are excluded from every public output.
